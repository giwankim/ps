# C++ Competitive-Programming Track Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a standalone `cpp/` competitive-programming track whose stdin/stdout solutions are discovered by glob, built with Homebrew g++-16, and tested by CTest running each binary against official sample files.

**Architecture:** One `cpp/CMakeLists.txt` globs judge directories and their `*.cpp` files, creating one executable target per problem. Each `tests/<problem>/*.in` file becomes one CTest test that runs the binary as a subprocess via `cmake/RunCase.cmake` and compares stdout against the sibling `.out`. Subprocess execution — rather than linking the solution into a test binary — gives a fresh process per case, captures C stdio, and needs no `main`-collision workaround, so solution files stay pristine and paste-able to the judge.

**Tech Stack:** CMake 3.24+, Ninja, Homebrew g++-16, C++23, CTest, clang-format.

**Spec:** `docs/superpowers/specs/2026-08-16-cpp-track-design.md`

## Global Constraints

- **CMake:** `cmake_minimum_required(VERSION 3.24)`.
- **Compiler:** `/opt/homebrew/bin/g++-16`, pinned in every preset. Never Apple clang — `<bits/stdc++.h>` and `__gnu_pbds` are libstdc++-only.
- **Standard:** C++23 via the `PS_STD` cache variable (default `23`), `CMAKE_CXX_EXTENSIONS OFF` so the flag is `-std=c++23`.
- **Cache variables:** `PS_SCOPE` (default `all`), `PS_STD` (default `23`), `PS_TIMEOUT` (default `5`).
- **Layout:** flat — `cpp/<judge>/<problem>.cpp`, data in `cpp/<judge>/tests/<problem>/<stem>.in|.out`.
- **Target naming:** `<judge>_<problem>` with characters outside `[A-Za-z0-9_.+-]` replaced by `_`.
- **CTest naming:** `<judge>/<problem>/<stem>` — keeps the original, unsanitized stem.
- **Comparison:** normalize **trailing** whitespace on both sides only. Leading whitespace is never normalized.
- **Stack:** all presets link `-Wl,-stack_size,0x4000000` (64 MB) under `if(APPLE)`.
- **Prose:** American English throughout.
- **Commits:** Angular style matching repo history — `feat(cpp):`, `build(cpp):`, `test(cpp):`, `docs(cpp):`.
- **Deferred, do not build:** the GoogleTest half (FetchContent, `<judge>_tests` targets, `.hpp` discovery), `cpp/tools/ps.py`, special-judge comparators, CI.

**Naming deviation from the spec:** the spec's example writes `-DIN=`. Use **`-DINPUT=`** instead — `IN` is a `foreach` keyword in CMake and a variable by that name is a readability trap. Task 3 includes a step to correct the spec.

```cmake
# --- discover judges -------------------------------------------------------
# A judge is any subdirectory of cpp/ other than cmake/ and build/. Adding a new
# judge therefore needs no edit to this file.
file(GLOB _entries CONFIGURE_DEPENDS "${CMAKE_CURRENT_SOURCE_DIR}/*")
set(judges "")
foreach(entry IN LISTS _entries)
  if(IS_DIRECTORY "${entry}")
    get_filename_component(_name "${entry}" NAME)
    if(NOT _name MATCHES "^(cmake|build)$")
      list(APPEND judges "${_name}")
    endif()
  endif()
endforeach()

foreach(judge IN LISTS judges)
  file(GLOB sources CONFIGURE_DEPENDS "${CMAKE_CURRENT_SOURCE_DIR}/${judge}/*.cpp")
  foreach(src IN LISTS sources)
    get_filename_component(problem "${src}" NAME_WE)
    string(REGEX REPLACE "[^A-Za-z0-9_.+-]" "_" safe "${problem}")
    add_executable("${judge}_${safe}" "${src}")
  endforeach()
endforeach()
```

Create `cpp/cmake/RunCase.cmake`:

```cmake
# Runs one solution binary against one .in file and compares stdout to its .out.
#
# Invoked by CTest as:
#   cmake -DEXE=<binary> -DINPUT=<file.in> -DEXPECTED=<file.out> -P RunCase.cmake
#
# The variable is INPUT rather than IN because IN is a foreach keyword in CMake.
#
# Comparison normalizes TRAILING whitespace only -- judges ignore it. Leading
# whitespace is preserved so a bug emitting a stray leading space still fails.

foreach(required EXE INPUT EXPECTED)
  if(NOT DEFINED ${required})
    message(FATAL_ERROR "RunCase.cmake: -D${required}= was not supplied")
  endif()
endforeach()

execute_process(
  COMMAND "${EXE}"
  INPUT_FILE "${INPUT}"
  OUTPUT_VARIABLE actual
  ERROR_VARIABLE stderr_text
  RESULT_VARIABLE exit_code)

if(NOT exit_code EQUAL 0)
  message(FATAL_ERROR "runtime error: exit ${exit_code}\n${stderr_text}")
endif()

file(READ "${EXPECTED}" expected)

function(ps_normalize text out_var)
  string(REPLACE "\r\n" "\n" text "${text}")
  string(REPLACE "\r" "\n" text "${text}")
  string(REGEX REPLACE "[ \t]+\n" "\n" text "${text}")
  string(REGEX REPLACE "[ \t\n]+$" "" text "${text}")
  set(${out_var} "${text}" PARENT_SCOPE)
endfunction()

ps_normalize("${actual}" actual)
ps_normalize("${expected}" expected)

if(actual STREQUAL expected)
  return()
endif()

# Escape ';' before splitting: CMake lists are semicolon-separated, so an
# unescaped ';' in the output would split one line into two.
function(ps_lines text out_var)
  string(REPLACE ";" "\\;" text "${text}")
  string(REPLACE "\n" ";" text "${text}")
  set(${out_var} "${text}" PARENT_SCOPE)
endfunction()

ps_lines("${expected}" expected_lines)
ps_lines("${actual}" actual_lines)
list(LENGTH expected_lines expected_count)
list(LENGTH actual_lines actual_count)

set(limit ${expected_count})
if(actual_count GREATER limit)
  set(limit ${actual_count})
endif()

math(EXPR last "${limit} - 1")
foreach(i RANGE 0 ${last})
  set(e "<missing>")
  set(a "<missing>")
  if(i LESS expected_count)
    list(GET expected_lines ${i} e)
  endif()
  if(i LESS actual_count)
    list(GET actual_lines ${i} a)
  endif()
  if(NOT e STREQUAL a)
    math(EXPR line_no "${i} + 1")
    message(FATAL_ERROR "output differs at line ${line_no}\n  expected: ${e}\n  actual:   ${a}")
  endif()
endforeach()

message(FATAL_ERROR "output differs but no differing line was found")
```

- [ ] **Step 1: Write the solution**

Ported from `atcoder/src/main/java/atcoder/abc471/a/Main.java`. Constraints and semantics are documented in `atcoder/src/test/java/atcoder/abc471/a/MainTest.java`: one line holds `A` and `B` with `1 <= A, B <= 100`. Print `Nine` when at least one of `A+B`, `A-B`, `A*B`, `A/B` equals 9, else `Nein`.

Two traps, both load-bearing:

- **`A-B` is signed and never reordered.** `B-A == 9` is not a match, so `1 10` answers `Nein`.
- **`A/B` is exact rational division, not the truncating integer quotient.** `A/B == 9` holds only when `A == 9*B`, so `19 2` (9.5) answers `Nein`. Writing a bare `a / b == 9` on ints truncates and wrongly answers `Nine` — the `a % b == 0` conjunct is what makes the division exact.

```cpp
#include <bits/stdc++.h>

int main() {
  std::ios_base::sync_with_stdio(false);
  std::cin.tie(nullptr);

  int a, b;
  std::cin >> a >> b;
  // a % b == 0 makes the quotient exact: a / b == 9 alone would truncate 9.5 to 9.
  bool nine = a + b == 9 || a - b == 9 || a * b == 9 || (a / b == 9 && a % b == 0);
  std::cout << (nine ? "Nine" : "Nein") << '\n';
  return 0;
}
```

````markdown
## Judge-environment parity

Local fidelity to the judge is a recurring concern, not a one-off — the Java
side carries `-Xss128m` in `boj/build.gradle.kts` and `-Xss64m` in
`ps.test-conventions` for the same reason. The C++ instances:

- **Stack.** macOS gives the main thread 8 MB; judges give more. All presets
  link `-Wl,-stack_size,0x4000000` (64 MB), so a deep DFS does not segfault
  locally on code the judge accepts.
- **libstdc++.** g++-16 provides `<bits/stdc++.h>` and `__gnu_pbds`.
- **Compiler version.** This is the gap C++23 introduces. Local g++-16
  implements more of C++23 than the judges' GCC does, so newer library
  additions (`<print>`, `std::ranges::to`, `std::mdspan`, `<stdfloat>`) can
  compile here and fail on the judge. The fallback needs no file edit:
  `cmake --preset dev -DPS_STD=20`.

## Testing model

Each `.in` file becomes one CTest test that runs the binary as a **subprocess**
and compares stdout to the sibling `.out`. Subprocess rather than in-process
because it gives a fresh process per case (so a global `int a[200005];` cannot
leak between cases), captures `printf`/`scanf` output, and survives a solution
calling `exit()`.

Comparison normalizes **trailing** whitespace only — judges ignore it, but a
bug emitting a stray leading space must still fail.

Two configure-time guards exist because an empty glob yields zero tests, and
zero tests pass green:

- a `.in` with no matching `.out` is a fatal error;
- a solution with no test data is a warning.

Function-signature judges (LeetCode, Programmers) are designed for but not yet
built — see the spec's "Deferred" section.
````
